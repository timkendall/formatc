# `src/md/`: Bun's Markdown parser (`bun_md`) in TypeScript

A port of `vendor/bun/src/md/*.rs` (without `ansi_renderer.rs`), file by file. `format/markdown` builds its tree from the
**events** of this parser (`vendor/bun/src/format/markdown/parse.rs`), so the whole event interface is ported, in
particular the "track" interface (`wantsSource`: where everything is written), the consumer's own syntax
(`Extensions`) and the formatter-only options (`micromark`, `mdx`, `footnotes`, ...).

Everything is checked against the Rust code: see "Tests" at the end.

## Files

| Rust (`vendor/bun/src/md/`) | TS (`src/md/`) | |
| --- | --- | --- |
| `lib.rs` | `lib.ts` | re-exports: **import from here** |
| `root.rs` | `options.ts` (`Options`, `Flags`), `root.ts` (entry points) | |
| `types.rs` | `types.ts` | enums as integer constants, `Renderer`, `Extensions`, `SpanDetail`, `Definition` |
| `parser.rs` | `state.ts` (the `Parser` state), `parser.ts` (`init`, `renderToHtml`, `renderWithRenderer`) | split to avoid import cycles |
| `blocks.rs` / `containers.rs` / `line_analysis.rs` / `ref_defs.rs` | the same names `.ts` | `impl Parser` blocks are functions that take `p: Parser` first |
| `inlines.rs` / `links.rs` / `autolinks.rs` / `render_blocks.rs` / `compat.rs` | the same names `.ts` | |
| `helpers.rs` / `unicode.rs` / `entity.rs` | `helpers.ts` / `unicode.ts` / `entity.ts` | tables are in `tables.ts` (generated, see below) |
| `html_renderer.rs` / `output.rs` | `html_renderer.ts` (output is a `ByteBuf`) | |
| `bun_collections::StringSet` | `labels.ts` (`LabelSet`) | byte strings -> dense ids |
| `bun_alloc` / `Vec<u8>` | `buf.ts` re-exports `ByteBuf`, `I32Vec` of `src/base/` | |

`tables.ts` is generated by `node tools/md/gen-tables.mjs` from the Rust sources (punctuation ranges, case folding maps,
the 2125 HTML entities, and `char::is_alphanumeric` of the pinned toolchain for `:::name`). They are compact strings that
are decoded the first time they are needed (a 50k-element array literal costs seconds of build time: cookbook section 8).

## Using it

```ts
import { Options, Renderer, Extensions, renderWithExtensions, SpanDetail, Definition,
         BT_P, SP_A, TX_NORMAL, BLOCK_FENCED_CODE /* ... */ } from "../md/lib.ts";

class Builder extends Renderer {                    // Rust: impl RendererImpl for Builder
  wantsSource(): boolean { return true; }           // asked once, before parsing
  enterBlock(blockType: number, data: number, flags: number): void { ... }
  leaveBlock(blockType: number, data: number): void { ... }
  enterSpan(spanType: number, d: SpanDetail): void { ... }   // d is reused: read it inside the call
  leaveSpan(spanType: number): void { ... }
  text(textType: number, buf: Uint8Array, start: number, end: number): void { ... }   // content = buf[start, end)
  lineStarts(starts: Int32Array, n: number): void { ... }
  containerSource(beg: number, end: number, indent: number): void { ... }   // beg === OFF_MAX (-1): end of document
  leafSource(blockType: number, lines: Int32Array, n: number): boolean { ... }  // n triples (beg, end, indent)
  inlineSource(beg: number, end: number): void { ... }
  extensionSpan(tag: number, buf: Uint8Array, start: number, end: number): void { ... }
  definition(d: Definition): void { ... }           // d is reused
}

const options = new Options();                      // defaults of Rust: tables, strikethrough, tasklists on
options.footnotes = true; options.mathBlocks = true; options.noSingleTilde = true;
options.micromark = true; options.micromarkToTheLetter = true; options.tasklists = false;
const rc = renderWithExtensions(text /* Uint8Array: exactly the document */, options, builder, extensions /* or null */);
// rc: 0, or ERR_INPUT_TOO_LARGE
```

HTML (what `Bun.markdown.html` does; test tool): `renderToHtmlWithOptions(text, options, out: ByteBuf)`.

scriptc notes (0.3.0): an overriding method must repeat the parameter list of `Renderer`/`Extensions` exactly (same
parameters, same types; `SC1090` otherwise), and `import * as fs from "node:fs"` (no default imports).

### What is different from Rust, and why

* **The document is the whole `Uint8Array`** (`text.length` is its size). All offsets are indices into it. Rust's
  `render_with_extensions(&text[first_line..], ..)` is `text.subarray(firstLine)` here (one allocation per file); the
  caller adds `base` where Rust's `Builder` does. A BOM is skipped (`subarray(3)`) only if the renderer does not
  want the source, as in Rust. `skipUtf8Bom(text)` is exported.
* **No `Result`**: callbacks return `void`. The parser cannot fail but for `ERR_INPUT_TOO_LARGE` (2 GiB). Rust's
  `StackOverflow` (a guard that never fires: the parser is iterative) and `TooManyBlocks` (4 GiB of block metadata) are not
  ported.
* **`&[u8]` slices are `(buf, start, end)`**: the bytes of a text event can be in the document or in a scratch buffer
  of the parser (merged lines of a paragraph), so there is always a `buf`. Valid during the call only.
* **`OFF::MAX` is `-1`** (`OFF_MAX`): `containerSource(beg = -1, ..)` at the end of the document. Nothing else is
  ever negative.
* **`SpanDetail` and `Definition` are single objects** that the parser fills in before each event. `href`/`title` are
  `hrefBuf[hrefStart, hrefEnd)` / `titleBuf[titleStart, titleEnd)` (empty: `start === end`, as `title.is_empty()`);
  `Definition`: `buf` with `label*`, `dest*`, `title*` ranges and `lines`/`linesFrom`/`linesCount` (triples).
* `BlockType`, `SpanType`, `TextType`, `Reference`, `Align`, `LineType`: integer constants `BT_*`, `SP_*`, `TX_*`,
  `REF_*`, `AL_*`, `L_*` in the order of the Rust enums (the numbers are the same: `BT_DOC = 0`, ... `BT_TD = 15`).
  `BLOCK_*` flags have the same values.
* `Options` is a class with the Rust field names in camelCase (`mathBlocks`, `noSingleTilde`, `micromarkToTheLetter`).
  `Options.terminal()` is `Options::TERMINAL`; `setByName("wikiLinks", true)` is the setter table of `Bun.markdown`.
* Per-thread, reusable, no allocation per document or per node: the parsers are objects that are reused (`acquireParser()`),
  every table is a grow-only typed array (`bb`: block headers and lines as Int32 words; `ed`: emphasis delimiters; `br`:
  brackets; `lf`: label frames; ...). **A parse may start inside a callback of another** (the formatter's
  `leaves_paragraph` does, from `text`): there is one `Parser` per level of nesting. Give the nested parse its own
  `Renderer` and `Extensions` objects: they carry state (`SpanDetail`/`Definition` belong to the parser).
* Link reference definitions are stored as byte ranges in `p.refBytes`; labels in a `LabelSet`.

## The consumer's own syntax: `Extensions`

Rust passes closures; here a subclass (`leaf` and `span` are methods):

```ts
import { Extensions, startsContainerInParagraph } from "../md/lib.ts";
import type { Parser } from "../md/lib.ts";

class MyExtensions extends Extensions {
  constructor() { super(); this.leafBytes = Buffer.from("{"); this.spanBytes = Buffer.from("$[{@:."); }
  // Rust: Extensions::leaf(&LeafStart) -> Option<OFF>.  -1: none
  leaf(p: Parser, off: number, indent: number, isInContainer: boolean, interruptsParagraph: boolean): number {
    // LeafStart::text is p.text; LeafStart::starts_container(line_beg) is startsContainerInParagraph(p, lineBeg)
  }
  // Rust: Extensions::span(&SpanStart) -> Option<ExtensionSpan>. The content is buf[off, off+len); pos, from, and the
  // result are relative to off. Return true after setting spanBeg, spanEnd, spanTag.
  span(buf: Uint8Array, off: number, len: number, pos: number, from: number,
       isAfterOpenBracket: boolean, serial: number): boolean { ... }
}
```

`SpanStart::content` of Rust is the slice `buf[off, off + len)`; `serial` is `SpanStart::serial`. The rules for a
returned span are those of Rust (`from <= spanBeg <= pos`, `spanBeg < spanEnd <= len`, else it is ignored). Memo keys
that Rust made from addresses (`bytes.as_ptr().addr() + index`) are `off + index` here: stable for one `serial`.

## What `format/markdown` uses (Rust -> TS)

| Rust (`parse.rs`, `strings.rs`, `html/lexer.rs`) | TS |
| --- | --- |
| `bun_md::root::{Options, render_with_extensions}` | `Options`, `renderWithExtensions(text, options, renderer, ext \| null): number` |
| `types::{BlockType, SpanType, TextType, Reference}` | `BT_*`, `SP_*`, `TX_*`, `REF_*` |
| `BLOCK_CLOSED, BLOCK_DIRECTIVE, BLOCK_EXTENSION, BLOCK_FENCED_CODE, BLOCK_FOOTNOTE, BLOCK_HTML_UNTIL_TEXT, BLOCK_SETEXT_HEADER` | the same names |
| `types::{Renderer, RendererImpl}` | `Renderer` (subclass it) |
| `SpanDetail { href, title, autolink, autolink_email, reference, .. }` | `SpanDetail { hrefBuf/hrefStart/hrefEnd, titleBuf/.., autolink, autolinkEmail, permissiveAutolink, autolinkWww, reference }` |
| `Definition { beg, end, label, dest, title, lines }` | `Definition` (see above) |
| `VerbatimLine { beg, end, indent }` | triples in an `Int32Array` |
| `Extensions`, `LeafStart`, `SpanStart`, `ExtensionSpan` | `Extensions` subclass (see above) |
| `OFF` | `number` (`OFF_MAX = -1`) |
| `JsResult<()>` | `void` |
| `bun_md::helpers::is_unicode_punctuation(c)` | `isUnicodePunctuation(c)` |
| `bun_md::helpers::decode_entity_to_utf8(text, &mut [u8; 8]) -> Option<&[u8]>` | `decodeEntityToUtf8(buf, start, end, out: Uint8Array): number` (length written into `out`, or -1) |
| `bun_md::compat::*` | `compat.ts` (reads `Flags`) |

Also exported for the formatter's own use: `isUnicodeWhitespace`, `findEntity`, `lookupEntity`, `decodeUtf8`,
`decodeUtf8Backward`, `encodeUtf8` (codepoint lengths in `UTF8.len`), `caseFold` (into `FOLD`).

## Tests (`tools/md/`, all run by `tools/md/run-tests.sh`)

* `src/md/unicode.test.ts`: the 14 tests of `unicode.rs`.
* `diff-html.ts` (bun): every `.md` of `bench/vscode` (371), Prettier's `markdown/` and `mdx/` fixtures and snapshot
  files (366), the CommonMark 0.31.2 examples and the GFM spec examples (1,324), and mutants of them, rendered with
  7 sets of options by the port and by `Bun.markdown.html`: byte for byte.
* `diff-events.ts` (node) against **the Rust parser itself** (`tools/md/rust-oracle`: the unmodified `vendor/bun/src/md`
  built with shims for `bun_core`; build: `tools/md/rust-oracle/build.sh`): every callback with all arguments, in order,
  for 12 option sets (track mode with the formatter's options, oxfmt's `directives`, MDX, plain, wiki links,
  permissive autolinks, ...), with test `leaf`/`span` hooks (the same hooks are in `rust-oracle/src/main.rs` and
  `events.ts`), over the corpora and structured/token-soup fuzzing.
* `diff-tables.ts`: case folding, punctuation/white space/alphanumerics for **all 1,114,112 codepoints**, entities,
  UTF-8 decoding vs. Rust; `diff-unicode-bun.ts`: all codepoints next to emphasis markers and as reference labels vs
  `Bun.markdown.html`; `diff-stress.ts`: quadratic traps and deep nesting vs. Rust.
* `reentrancy.ts`: parses started inside callbacks (3 levels) do not change the result of the outer parse.
* `compiled-check.ts`: hashes everything the port outputs; the scriptc build and `node` print the same number.
* `bench.ts`: throughput (`scriptc build tools/md/bench.ts -o /tmp/mdbench`).

Not testable against Bun from JS: the options `footnotes`, `mathBlocks`, `directives`, `noSingleTilde`, `micromark`,
`micromarkToTheLetter`, `mdx` (not exposed by `Bun.markdown`) and `latexMath`/`underline` (no effect on `html`): those
are covered by the Rust oracle only.
